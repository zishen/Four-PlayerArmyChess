# 软件需求规格说明

## 1. 文档状态

本文档建立当前可执行原型的需求基线。需求状态分为“已实现”“部分实现”“规划中”。只有“已实现”项可作为当前版本能力声明。

## 2. 产品目标

在 Windows 桌面环境提供一局可操作的四国军棋原型：用户控制下方的 3 号位，其余席位自动行动；系统执行基本布阵、移动、战斗、信息隐藏、出局和团队胜负规则。

## 3. 用户与范围

主要用户是本地单机玩家。当前范围包含单窗口、自动布阵、一名本地玩家、三个策略 AI（可设难度）、大模型对手、规则执行、走子记录/存档/复盘和简单声音/动画反馈。

当前范围不包含网络对战、多人本地轮流、手动布阵、计时钟、历史战绩库、聊天、账户、安装程序和自动更新。`doc/design.md` 中其余内容属于产品愿景，不是已交付功能。

## 6. 业务规则基线

棋盘以 17×17 十字拓扑、129 个通行节点、20 个行营、4 个大本营（每翼 1 个）建模，与 `doc/rules.md` 第一章一致（决策 C1/C2）。席位固定为 1=上、2=右、3=下、4=左；对家（1↔3、2↔4）结盟，行棋按 1→2→3→4 顺时针（决策 C2/C3）。

大本营仅可放置军旗，且对局中不可走入；只有吃掉大本营上的敌方军旗时可进入该点（决策 C9），由 `Board.FlagAnchor`、`SetupPiece` 与 `canOccupyDestination` 保证。

普通棋子沿铁路 **直行连续多格**；仅在四个 **弯道**（中央四角 (6,6)/(6,10)/(10,6)/(10,10)）处可沿其连接的 **相邻两方翼** 不停下转向（如 (10,10) 连下方翼↔右方翼），**不能从弯道直插中央**；**直角路口必须停下、不可拐弯**。例：(9,11) 需分三步到 (11,9)；(10,13) 经弯道 (10,10) 一步直达 (13,10)；炸弹从 (14,6) 到弯道 (10,6) 只能拐入上方翼 (10,5)，不能直插中央去 (10,13)。工兵可沿铁路到达任意无阻挡的交叉点（含任意拐弯）。每翼铁路相对 **最外一排内缩一排**：最外一排/列（大本营所在排）为纯公路。**处于铁路上的棋子（含工兵）本回合只能沿铁路滑行，不能一步踏上相邻普通公路；仅可一步进入相邻行营，或一步踏上大本营所在的最外一排/列（该排是大本营唯一出口，否则任何棋子都无法夺旗）。** 由 `TestRailwayTurnOnlyAtCurves`、`TestBombCannotCutAcrossCenterCorner`、`TestRailCannotStepOntoOrdinaryRoad`、`TestRailPieceCanStepIntoAdjacentCamp`、`TestRailCanReachOutermostLine`、`TestHeadquartersReachableAndFlagCapturable`、`TestFlagCannotMove`、`TestBackRowIsRoadNotRailway`、`TestOrdinaryPieceSlidesStraightAndStopsAtRightAngle` 与 `TestEngineerReachesWholeRailwayNetwork` 固定（决策 C5）。

行营保护为“在营即免疫”（移入即生效），由棋子所在位置实时判定（决策 C6）。

对家（对角席位）互为队友，紧邻席位互为对手。棋子不能进入或以吃子方式占用队友棋子所在交叉点，该约束由 `canOccupyDestination` 与 `TestTeammatesCannotCaptureEachOther` 保证（决策 C11）。

一方司令阵亡（被炸弹炸、触地雷或与对方司令同归于尽）后，该方军旗位置对外公开；由 `Game.revealFlag`、`Game.MarshalDead` 与 `VisiblePieces` 实现，并由 `TestFlagRevealedWhenMarshalDies` 保证。

地雷交互：工兵挖雷 → 工兵存活、地雷移除；炸弹触雷 → 双方同归于尽；其他棋子触雷 → 该棋子消失、**地雷保留**；由 `ResolveCombat` 及 `TestNonEngineerDiesAndLandmineRemains`、`TestBombAndLandmineDestroyEachOther` 保证。

对局节奏：每一步走完后暂停约 0.5 秒（GUI `aiMoveDelay` / `replayDelay`），便于观察走子与复盘。

占领（吃掉）对方军旗的棋子停在军旗交叉点并永久不可再移动；该约束由 `Piece.Immobile` 与 `TestPieceThatCapturesFlagBecomesImmobile` 保证（决策 C11）。

僵局（四方均无合法走法）按剩余子力判定：先比较棋子价值总和，再比较棋子数量，平局判和（决策 C7），由 `Game.Adjudicate` 保证。

人机对战中 AI 遵循信息隔离：仅依据己方棋子与已交互揭示的敌方棋子类型推理，未识别棋子按剩余类型分布估计战斗结果（决策 C8），由 `Piece.Known`、`aiContext.unknownPool` 与 `TestCombatRevealsTypesToParticipantsOnly` 保证。原型首回合默认人类（3 号位）先手（决策 C4），交互以音效+落子/移除反馈、不弹窗（决策 C10）。
